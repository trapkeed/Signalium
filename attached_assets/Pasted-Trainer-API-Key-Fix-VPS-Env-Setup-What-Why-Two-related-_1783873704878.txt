Trainer API Key Fix & VPS Env Setup
What & Why
Two related gaps need closing before the Research Lab section works in production:

trainer.api_key is never sent. The labFetch function in researchLab.ts (and qdeTrainer.ts) only sends the SSO JWT as Authorization: Bearer <token>. The trainer backend expects the shared secret (RESEARCH_LAB_ADMIN_TOKEN) but never receives it, so every request returns 503.

Missing env vars on the VPS server. The server/.env on the VPS is missing several variables the platform reads at startup. These need to be documented clearly and patched into the running server.

Done looks like
Research Lab section in the admin UI shows live data instead of "unavailable"
labFetch and qdeTrainer send the trainer.api_key vault value as an X-Trainer-Api-Key header on every outbound request to the trainer
A shell snippet is produced that the user can paste into their VPS SSH session to patch server/.env in one go and restart PM2
Startup diagnostic shows research_lab: ok and trainer: ok
Out of scope
Changing how the trainer backend validates the key (that's on the trainer side)
Setting up object storage / PRIVATE_OBJECT_DIR (not needed for Research Lab)
SMTP or payment provider configuration
Steps
Send trainer.api_key in outbound requests — In labFetch (researchLab.ts) and the equivalent fetch wrapper in qdeTrainer.ts, read trainer.api_key from the vault via resolveManagedConfig and, if present, append it as an X-Trainer-Api-Key header alongside the existing Authorization header.

Rebuild and package — Run build-release.sh (or the equivalent pnpm --filter @workspace/api-server build), zip the updated server/ folder into server.zip and present it for FileZilla upload.

Produce VPS env patch snippet — Output a ready-to-paste cat >> /var/www/signalium/server/.env block for the variables that are missing but have sensible defaults:

JWT_ISSUER=signalium
JWT_EXPIRATION=300
JWT_REFRESH_EXPIRATION=30 Include a reminder to set RESEARCH_LAB_ADMIN_TOKEN=<same value as trainer.api_key> on the trainer side and restart PM2 with pm2 restart signalium-api.
